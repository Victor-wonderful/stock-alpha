## 0. 왜 이걸 하는가 (브레인스토밍 결정 기록)

| 질문 | Victor 결정 |
|---|---|
| 첫 고객 | 직접 매매하는 개인 트레이더 + 바쁜 직장인 개인투자자 (둘 다) |
| 돈 낼 이유 | 규율·픽·리포트·패턴 검증 네 가지 모두 — 단, 정문은 하나 |
| 정문(방향) | **B안 — 「오늘의 픽」 중심 유지** (A 내 종목 지킴이 · C 리서치 터미널 기각) |
| 첫 목표 | **따라 하기 쉽게** (성과 개선 · 성적표 · 사람 모으기보다 먼저) |
| 채널 | **텔레그램 먼저**, 카카오 알림톡은 사용자가 늘면 추가 |

당시 사실(2026-10-09 DB): 가입 12명 · 최근 7일 로그인 0명 · 시가진입 규칙(8/21) 이후 끝난 픽 47건 평균 -0.8%/건(이긴 건 16건).
→ 픽을 따라 하려면 사용자가 매일 사이트에 들어와 숫자를 챙겨야 한다. 특히 «추격 중» 손절값은 매일 바뀌는데 알려 주는 곳이 없다.

## 1. 사용자가 픽 하나를 따라 할 때 하는 일

| 시점 | 할 일 | 지금 | 이 설계 후 |
|---|---|---|---|
| 전날 밤~09:00 KST | 시가 매수 주문 | 사이트에 와야 보임 | 저녁 알림 + 아침 리마인더 |
| 매수 직후 | 수량 계산, 손절 주문 | 비중 %만 | 주문표에 수량·금액·손절가 [복사] |
| 목표 도달 뒤 | 손절을 매일 «고점 − 1R» 로 올리기 | 「추격 중」 칩만 | 「손절 올리기 A → B」 할 일 |
| 청산 기한 | 그날 종가 전량 매도 | 날짜만 | 「○요일 종가 매도」 할 일 |

## 2. 알림 (설계 ①)

엔진은 장 마감 뒤 하루 한 번 계산한다 → **장중 실시간 알림은 하지 않는다.**

- **저녁 알림** — 일일 배치 완료 직후(보통 21시 KST), 회원당 **하루 1통**으로 묶음.
  섹션: 새로 사기(다음 거래일 시가) · 손절 올리기 · 팔기(청산 기한) · 오늘 끝난 거래 · [내 주문표 열기].
  할 일이 없는 날도 「오늘은 할 일이 없습니다」 한 줄을 보낸다(같은 시간 확인 습관).
- **아침 리마인더** — 08:00 KST, **새로 살 픽이 있는 날만**. 「오늘 시가 매수 N건 · 종목명」.
- **운영 알림(Victor 전용)** — 같은 봇. 배치 실패 · 뉴스 수집 0건 · 픽 0건 이틀 연속 · 알림 지연.
- 메시지 끝 면책 한 줄: 「투자 판단의 책임은 본인에게 있습니다」.
- v1 제외: 장중 알림 · 픽별 개별 알림 · 주간 성적 요약.

## 3. 연결과 내 주문표 (설계 ②)

### 텔레그램 연결 (회원만)
1. `/alerts` 의 [텔레그램 연결] → 일회용 연결 코드(10분 유효) 발급 → `t.me/<봇 아이디>?start=<코드>` 로 이동 (봇 아이디는 BotFather 생성 때 정함)
2. 봇 [시작] → 웹훅이 코드를 확인하고 회원 ↔ chat_id 저장 → 봇이 「연결됐습니다」 회신
3. 해제: 봇 `/끄기` 또는 사이트 [연결 해제]. 사용자가 봇을 차단(403)하면 자동 해제.
- 저장은 chat_id 하나. 본인만 읽는 RLS.

### 내 주문표 (새 화면, 회원만)
- 투자 금액을 한 번 입력(저장). 픽마다 **수량과 금액을 함께** 표시: 「35주 · 약 77만 원」.
- 수량 = floor(권장 비중 × 투자 금액 ÷ 진입가). 모든 회원 같은 공식(일반 로직 — 1:1 맞춤 자문 아님).
- 행 종류: 시가 매수 · 손절 주문 [복사] · 손절 올리기 A → B [복사] · 종가 매도.
- 실제 매수 여부는 VECTA 가 모른다 → 「VECTA 픽 기준 할 일」로 표기. 체크 기능은 v1 제외.
- 목업: 2026-10-09 브레인스토밍에서 확인(색: 매수=시세 상승색, 손절=액센트, 손절 올리기=경고, 매도=회색). 768px 미만은 카드.

## 4. 구조와 예외 처리 (설계 ③)

### 단일 출처 원칙
**«할 일 목록»은 엔진이 한 번만 만든다.** 텔레그램과 주문표는 읽기만 한다 — 두 화면이 다른 숫자를 말하는 사고(홈 vs 성과)를 반복하지 않는다.

```
[엔진 일일 배치] → pick_actions(날짜별 할 일) → notification_outbox → [발송기] → 텔레그램
                                            ↘ [웹] 내 주문표
[텔레그램 /start] → [웹 API 웹훅] → telegram_links
```

### 선행 수정 — 추격 손절값 저장
현재 «추격 중» 픽의 유효 손절(고점 − 1R, 하한 진입가)은 **저장되지 않는다.** 엔진(`daily.resolve_pick_status`)과 웹(`lib/data.ts` getPeakHigh)이 각자 계산한다.
→ 엔진이 매일 `recommendations` 에 현재 유효 손절(예: `trail_stop`, `trail_stop_at`)을 저장하고, 웹·주문표·알림은 그 값을 읽는다. 웹의 자체 계산은 제거.

### 새 저장소 (마이그레이션, `packages/db`)
| 테이블/컬럼 | 내용 | 접근 |
|---|---|---|
| `recommendations.trail_stop`, `trail_stop_at` | 현재 유효 손절 | 공개 읽기(기존과 동일) |
| `pick_actions` | as_of, recommendation_id, kind(buy/stop/raise_stop/sell/closed), price, prev_price, weight, due_date | 회원 읽기, 쓰기는 엔진만 |
| `telegram_links` | user_id, chat_id, active, linked_at | 본인만(RLS) |
| `telegram_link_codes` | code, user_id, expires_at, used_at | 서버만 |
| `profiles.invest_amount` | 투자 금액 | 본인만 |
| `notification_outbox` | user_id(또는 ops), kind(evening/morning/ops), for_date, body, status, attempts, sent_at · **unique(user_id, kind, for_date)** | 서버만 |

### 실패·예외
- 발송 실패 → 최대 3회 재시도 → 그래도 실패면 Victor 운영 알림.
- 403(차단) → `telegram_links.active=false`, 사이트에 「연결 끊김」.
- 23:00 KST 까지 배치 미완료 → 회원 발송 안 함, Victor 에 「오늘 알림 지연」. 틀린 할 일보다 무발송이 낫다.
- 배치 재실행 → unique 키로 중복 발송 없음.
- 시간: 운영 PC 는 MSK(UTC+3). 08:00 KST = 02:00 MSK 로 예약 작업 등록.

### 보안
- 봇 토큰은 엔진·서버 환경변수만(`.env.example` 에 이름만). 클라이언트 노출 금지.
- 웹훅은 텔레그램 `secret_token` 헤더 검증.
- chat_id·투자 금액은 본인 RLS. 운영 알림 수신자는 환경변수로 고정.
